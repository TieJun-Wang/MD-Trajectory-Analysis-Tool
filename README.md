## 1. 快速开始

### 环境

- Python 3.10+（本工具在 Python 3.13.5 上开发与验证）

### 支持的拓扑 / 轨迹格式

**拓扑文件**（第一个参数）：

| 格式 | 是否支持 | 化学键 | 元素 | 说明 |
|---|---|---|---|---|
| `.tpr` | ✅ 首选 | ✅ 自带键表 | ✅ | GROMACS 运行输入，信息最完整 |
| `.gro` | ✅ | ❌ 无键表 → **自动猜键** | ❌ → 按残基名/原子名推断 | 只需第 2 行的原子数，读取很快 |
| `.pdb` | ✅ | ⚠️ 仅 `CONECT` 记录 | ✅ | 多数 MD 输出的 pdb 没有 CONECT，因此同样自动猜键 |
| `.psf` / `.prmtop` / `.parmed` | ✅ | ✅ | ⚠️ | 由 MDAnalysis 读取 |
| `.top` | ❌ **明确拒绝** | — | — | GROMACS 力场拓扑，MDAnalysis 无法解析；会给出可操作的提示，而不是抛晦涩错误 |
| `.xyz` / `.pdb1` / `.ent` | ✅ | ❌ → 自动猜键 | 部分 | — |

**轨迹文件**（第二个参数，可省略）：`.xtc` `.trr` `.dcd` `.nc` `.gro` `.pdb` `.xyz` `.lammpstrj` 等，
凡 MDAnalysis 支持的格式都能用。

#### 没有化学键时的「自动猜键」

`.gro` / 无 `CONECT` 的 `.pdb` 都不含键信息，而 Rg、二面角、链识别都需要键。
本工具用**共价半径判据**自行推断：

$$|r_i-r_j| < f_{udge}\cdot(R_i+R_j),\qquad f_{udge}=1.2$$

- 共价半径表覆盖全部元素（Pyykkö 单键共价半径），缺失元素不会导致整条链断裂；
- **单原子离子（Na⁺、Cl⁻、Li⁺、Cu²⁺ 等）不参与成键**判据，否则会被错误地"粘"到最近的
  水分子上，把水分子拼成十几到几十个原子的大碎片；
- 零半径/虚拟位点（`DUMMY`）永不参与成键；
- 猜键结果会与 `.tpr` 交叉验证：同一体系用 `.tpr` 与 `.gro` 得到**完全一致**的键数
  （AdK：25533 键 / 22173 个碎片；生物聚合物：24020 键 / 654 个碎片）；
- 原子数超过 30 万的体系默认跳过自动猜键（只影响依赖键的分析）；
- 猜键信息（键数、碎片数、耗时）会写入结果说明，便于核查。

> `.gro` 的原子数在**第 2 行**（第 1 行是标题）。工具据此在拓扑与轨迹原子数不一致时，
> 主动在同目录里扫描原子数匹配的候选拓扑文件并给出建议。

## 3. 三种使用方式

| 入口 | 图表 | 适合场景 |
|---|---|---|
| **Web 版**（`webapp/`） | 浏览器内交互图（缩放 / 平移 / hover / 图例开关） | 看图、演示、给导师看、远程访问 |
| 桌面操作台（`mdta_gui.py`） | 界面内不画图，数据表 + 导出 PNG | 本机操作台，看数值、导数据 |
| 命令行（`mdta_cli.py`） | 导出 PNG（`--panel-pngs` 可一图一文件） | 批量、脚本化、服务器上跑 |

三者共用同一套分析代码（`mdta` 包），**计算结果完全一致**。

### 3.0 Web 版（推荐）

```powershell
python -m pip install -r webapp\requirements.txt
cd webapp\frontend; npm install; npm run build; cd ..\..
python -m webapp.backend.run          # 打开 http://127.0.0.1:8000
```

FastAPI 后端 + React 前端，详见 [`webapp/README.md`](webapp/README.md)。

**实时更新**：分析**每算完一项就立刻出现在页面上**，不用等全部跑完。
以 Abeta 板层体系（40 896 原子 / 10 项分析 / 总 18.3 s）为例：

```text
0.4s  rg、ree       ← 第一张图已经可以看了
0.8s  dihedral
1.3s  density
6.8s  rdf
16.2s contact
16.6s  interface
17.0s  orientation
17.5s  order
18.3s  msd
```

界面左上会显示 `● 实时更新中` 徽标、`分析中… 4/10`、真实进度条、
当前正在算哪一项、以及「排队中」的剩余项；「取消（保留已算完的）」
会真的让后端停下，已算完的图全部保留。

**先预估用时，再按短 → 长跑**（1.0.1 新增）：点「开始分析」后，后端会先给
每个勾选项**各跑几帧实测**，把「固定开销 + 每帧代价」两点拟合外推成整段用时
（不是按规模拍系数 —— 各项分析的常数因子差好几个量级），然后按用时从短到长
执行，让结果尽早出现。46 体系（47 453 原子 / 10 001 帧）实测：

```text
预估阶段 17 s（占预计总时长 ~0.2%）
  msd          ≈ 100 s     ← 最先出图
  interface    ≈ 289 s
  orientation  ≈ 381 s
  contact      ≈ 2149 s
  order        ≈ 2203 s
  rdf          ≈ 4076 s    ← 最贵，排在最后
预计总用时 ≈ 2.55 小时
```

同一体系上预估与实际吻合得很好（AdK：预估 msd 0.25 / rg 1.33 / rdf 18.12 s，
实际 0.21 / 1.31 / 17.25 s）。顶栏第二行常驻「当前分析项：径向分布函数 RDF
（预计 1 h 8 min）· 排队 5 项」，分析功能里每一项后面也会标出 `≈` 预估用时。

帧数太少（< 40）时**会自动跳过预估**并在界面上说明原因 —— 预估本身要跑几帧，
小体系里这笔开销可能比正式分析还大（AdK 10 帧：预估 12 s、正式跑 18 s）。
「运行」区有一个开关可以完全关掉预估，按勾选顺序直接跑。

左侧操作栏可以**整体折叠**：最左侧常驻一条 26px 竖条，展开时显示
「收起操作台」、收起时显示「展开操作台」，位置始终不变。宽度用 240ms 过渡
让给图表，图表导航与图表区**平滑展开**（面板内容保持固定宽度不重排，
ECharts 侧用 `ResizeObserver` + `requestAnimationFrame` 把动画期间的 resize
合并成每帧一次）。

页面是**三栏布局**：`[左：操作台] [中：结果区] [右：图表说明]`。
原来压在图表下方、把图挤得很矮的**算法说明 + 关键统计量**已移到右侧独立栏
（同样可折叠，竖条在最右侧，内容跟随当前正在看的那张图）；
图表区因此拿到整块高度。图表标题栏还有「**⤢ 全屏**」按钮，
优先用浏览器 Fullscreen API，被拒绝时自动退化成整页覆盖，`Esc` 退出。

左右两栏**互斥**（屏幕宽度有限）：展开一边就自动收起另一边；
**一点「开始分析」就立刻**收起操作台、展开说明栏，把屏幕让给图表
（进度改在顶栏显示，不会丢）。

「2. 体系信息」的完整报告是**表格**（9 个小节），不再显示定宽文本报告：
只纵向滚动、**横向锁死**，长文件名/分组名自动换行。
右侧说明栏也一样：说明用悬挂缩进（9.5px + 圆点项目符号）、
统计量用固定列宽的表格，超宽自动换行，**纵向可滚、横向锁死**。

图表导航、数据表导航、统计量板块都是**按大纲模块分层**：
链构象 / 空间结构 / 取向与结晶 / 动力学与输运。分组定义在后端 `mdta.pipeline.ANALYSIS_GROUPS`，
前后端共用一份；模块只显示已经有结果的那些，实时运行时一项项长出来。

统计量页每项分析是**带表头的表格**（统计量 | 数值），导出文件清单也是表格。
所有表格的单元格统一**水平居中 + 垂直居中** —— 这一条由真实浏览器逐格验证
（`webapp/_test_layout.mjs`，Headless Chrome + CDP）。

「分析功能」区有一排快捷预设：**全选 / 仅构象 / 仅结构 / 仅取向 / 仅输运**
（5 个按钮强制排在**一行**；按钮用 2 字缩写、完整分组名在悬停提示里，因为
「仅动力学与输运」这类完整名会把整行挤爆），当前勾选正好等于某一类时按钮会高亮。

### 3.1 桌面操作台（Tkinter）

```powershell
python mdta_gui.py                                     # 空白启动
python mdta_gui.py adk_oplsaa.tpr adk_oplsaa.xtc       # 直接带文件启动
python mdta_cli.py gui                                 # 同上
```

> **定位：操作台 + 数据台，界面内不画图表。**
> 它负责选文件、选对象、设参数、跑分析、看数值、导出结果；
> 图表由导出功能生成 PNG 文件（或用后续的 Web 前端渲染）。

界面布局（**固定，无拖拽**）：左侧操作面板宽度恒定，右侧数据区自适应剩余
空间，中间没有可拖动的分隔条。

```text
┌──────────────────────────────────────────────────────────┐
│  MD Trajectory Analysis Tool                             │
├────────────────┬─────────────────────────────────────────┤
│ 1. 轨迹文件     │ [分析结果] [汇总] [统计量明细] [运行日志]│

│ 3. 分析对象选择 │  │ 分析/数据表 │  当前数据表的行与列    │ │
│ 4. 参数设置     │  │  ▸ 回转半径 │  [导出当前表] [复制]   │ │
│ 5. 分析功能     │  │  ▸ 二面角   │                       │ │
│ 6. [开始分析]   │  └────────────┴───────────────────────┘ │
├────────────────┴─────────────────────────────────────────┤
│ [导出全部] [CSV] [PNG] [Excel] [打开输出目录]  输出目录:… │
├──────────────────────────────────────────────────────────┤

└──────────────────────────────────────────────────────────┘
```

四个页面：

| 页面 | 内容 |
|---|---|
| **分析结果** | 左边是"分析 → 数据表"目录树（如 Rg 有 `rg__panel0`、`rg__panel1`），点一下右边显示该表的行列；可「复制当前表」直接粘进 Excel，或「导出当前表 CSV」 |
| **汇总** | 一行一个分析（标题、数据表数、统计项数），点击跳到该分析的数据表 |
| **统计量明细** | 全部标量结果 + 算法说明，按分析分组 |
| **运行日志** | 读取体系、运行分析、导出文件的完整过程记录，可清空 |

使用步骤：

1. 点「选择…」选 `.tpr`，若同目录有同名 `.xtc` 会自动填入；
2. 点「读取体系信息」，左侧显示原子数、残基、模拟盒、分子/链清单；
3. 在「分析对象选择」里选主链（默认自动取最大的链），勾选参与界面分析的组分；
4. 在「参数设置」里填时间范围/间隔、cutoff、密度方向等；
5. 勾选要跑的分析功能，点「开始分析」；
6. 分析完成后在「分析结果」页看数据表，或到「统计量明细」页看全部数值；
7. 点「导出全部结果」生成 CSV / PNG / Excel，再点「打开输出目录」查看图表。

> 分析在后台线程运行，界面不会卡死；进度条与状态栏实时显示当前分析项。

#### 图表怎么看

桌面界面**不做图表渲染**（Tkinter 内嵌 matplotlib 在缩放屏上体验不好、交互也
受限，所以把它从界面里去掉，只保留数据与导出）。图表通过导出得到：

- 「导出全部结果」或 `mdta_cli.py run` → 每个分析一张合并 PNG
  （`rg.png`、`contact.png` …），可直接插论文；
- 加 `--panel-pngs` → 再把**每个面板**单独导出成
  `contact__p1.png` … `contact__p4.png`，一张一张看。

```powershell
python mdta_cli.py run -t sys.tpr -x sys.xtc --panel-pngs -o results
```

界面底部还有「打开输出目录」，一键用资源管理器打开结果文件夹。

#### 高清显示（高 DPI / 缩放屏）

界面已专门处理 Windows 显示缩放，在 125% / 150% / 175% / 200% 等缩放设置下
文字都是**按真实像素渲染的，不会发虚**：

| 处理 | 说明 |
|---|---|
| 进程 DPI 感知 | 启动时调用 `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`，避免 Windows 把窗口位图拉伸 |
| Tk 缩放 | `tk scaling` 设为 `显示缩放 × 96/72`，字体与控件尺寸按真实 DPI 换算 |
| 窗口尺寸 | 按屏幕物理分辨率自适应（并留边距），不会超出屏幕 |
| 导出 PNG | 每张图独立按 `--dpi`（默认 200）渲染；单面板图尺寸精确可复现（`pixel_figsize`） |

如果系统 DPI 探测不准，可以用环境变量强制指定缩放：

```powershell
$env:MDTA_GUI_SCALE = "1.5"      # 1.25 / 1.5 / 1.75 / 2.0 …
python mdta_gui.py
```

> 导出图片不受屏幕缩放影响，始终以 200 dpi 保存（`--dpi` 可调）。

### 3.2 命令行

```powershell
# 查看体系信息
python mdta_cli.py info -t adk_oplsaa.tpr -x adk_oplsaa.xtc

# 列出分子/链，用来确定主链的选择语句
python mdta_cli.py chains -t adk_oplsaa.tpr --min-atoms 20

# 列出所有可用分析项
python mdta_cli.py list

# 全部分析 + 导出
python mdta_cli.py run -t sys.tpr -x sys.xtc -o results

# 只跑链构象分析，跳过前 20 ns，每 100 ps 取一帧，接触 cutoff 取 4 Å
python mdta_cli.py run -t sys.tpr -x sys.xtc `
    --which rg,ree,dihedral --equil 20000 --interval 100 --cutoff 4 -o results

# 指定主链（MDAnalysis 选择语句）与组分
python mdta_cli.py run -t sys.tpr -x sys.xtc `
    --primary "segid seg_0_PE" --components "seg_0_PE,seg_1_PEO"

# 批量分析一个目录
python mdta_cli.py batch .\md_data -o .\results --interval 100 -o results
```

主要参数：

| 参数 | 含义 | 默认 |
|---|---|---|
| `-t/--top` | 拓扑文件（必填） | — |
| `-x/--traj` | 轨迹文件（可省略，自动找同名 `.xtc`） | 自动 |
| `--start/--stop` | 参与分析的时间区间 (ps) | 全轨迹 |
| `--equil` | 平衡段长度 (ps)，其内数据不参与统计 | 0 |
| `--interval` | 抽帧间隔 (ps) | 每帧 |
| `--max-frames` | 最多使用的帧数 | 不限 |
| `--primary` | 主链选择语句 | 最大链 |
| `--components` | 参与界面/RDF/MSD 的组分（逗号分隔） | 自动识别 |
| `--cutoff` | 接触判据截断距离 (Å) | 5.0 |
| `--axis` | 密度/界面分析方向 0=a,1=b,2=c | 2 |
| `--nbins` | 密度分布 bin 数 | 100 |
| `--rmax` / `--rdf-bins` | RDF 最大距离 / bin 数 | 12 Å / 120 |
| `--dihedral-mode` | `auto`/`phi_psi`/`chain`/`topology` | auto |
| `--g-ref` | 结构有序度里"完全有序态"的 RDF 堆积峰高度 | 不参与综合指数 |
| `--which` | 要运行的分析项 | 全部 |
| `-o/--outdir` | 输出目录 | `analysis_results` |
| `--formats` | 导出格式 `csv,png` | `csv,png` |

## 4. 分析功能详解

所有分析统一返回 `AnalysisResult`，包含：

- `curves`：若干条曲线（每个面板一张子图）
- `summary`：标量统计量（自动汇总进 `summary.xlsx`）
- `notes`：算法与判据的文字说明（导出在统计量明细里）
- `to_dataframe()` / `plot()` / `dataframes()`

### 4.1 链构象分析

#### Rg — 回转半径

$$R_g=\sqrt{\frac{\sum_i m_i|\mathbf r_i-\mathbf r_{cm}|^2}{\sum_i m_i}}$$

- 输出：Rg–Time 曲线 + 平均线、Rg 分布、平均值/标准差/标准误/**块平均标准误**
- 关键点：默认在 **PBC 展开后**的坐标上计算（见 [5.1](#51-周期性边界条件)）
- 参数：`mass_weighted=True` 质量加权（可改为等权重）
- **按分子统计**（1.0.1 起）：组分含多个分子时，除整组 Rg 外还**逐个分子**算 Rg，
  给出「单分子 Rg 平均/标准差/最小/最大」与逐分子面板。
  例：46 体系 polymer 组分（253 个分子）整组 Rg = 45.35 Å，而单分子 Rg = 7.79 Å
  ——**整组那个数是"整团物质"的回转半径，不是"分子有多大"**，1.0.0 只给前者。
  质量信息缺失时退化为等权重（几何）Rg 并注明。

#### R_ee — 端到端距离

- 输出：R_ee–Time 曲线、R_ee 分布、平均值/标准差，以及链端来源与端原子标签
- **链端由键连接图确定**（1.0.1 起，不再是"首尾原子"）：
  - 蛋白质 → 主链端基（首个残基 N / 末个残基 C）。蛋白质里"度为 1 的原子"
    包含全部末端氢与侧基末端原子（AdK 实测 1982 个），按键图找端会选到侧链；
  - 线形高分子 → 键图中度为 1 的两个原子；
  - 支化链/带侧基 → 取键图**直径**两端，并明确标注这是约定；
  - **环状分子/交联网络 → 拒绝给出 R_ee**（没有端基，这个量没有定义），
    结果里写明原因，曲线数为 0；
  - 组内含多个分子 → **逐分子各算自己的 R_ee**（各自找端原子），
    并报出无法定义而被跳过的分子数。
- 兼容：`ends="selection"` 复现 1.0.0 的旧口径（首尾原子），
  `atom_indices=[i, j]` 显式指定两个端原子。
- 实测差异（AdK 蛋白）：旧口径 9.911 Å（MET1(N)–GLY214(O2)）→ 新口径
  10.198 Å（MET1(N)–GLY214(C)），差 2.9%；46 polymer：旧口径对整个
  45,005 原子集合给一个数，新口径给出 252 条链各自的 R_ee（平均 19.10 Å）。

#### 二面角

- 模式：`auto`（蛋白→φ/ψ，其它→几何连续原子）/ `phi_psi` / `chain` / `topology` / `custom`
- `chain` 自 1.0.1 起更名并明确为**几何连续原子模式**：它给的是"沿键图最长路径
  连成一串的原子"之间的二面角，**不保证**等于化学意义上的主链/重复单元二面角
- `gauche_edge` 参数化 trans/gauche 分界角（度，默认 120），结果里写明本次阈值

四种模式：

| 模式 | 说明 | 适用体系 |
|---|---|---|
| `phi_psi` | 蛋白质主链 φ / ψ | 蛋白质、多肽 |
| `chain` | 从键连接图提取**最长路径**作为链骨架，取连续四原子二面角 | 线形高分子 |
| `topology` | 使用拓扑文件中已定义的二面角 | 力场已定义二面角的体系 |
| `custom` | 用户给出 `(n, 4)` 原子索引 | 指定官能团 |

- 输出：二面角分布、trans/gauche 构象比例随时间变化、部分二面角的时间序列
- 统计量：圆统计平均角、圆统计量 R、trans / gauche+ / gauche- 比例
- 判据：`|φ| > 120°` 为 trans（`gauche_edge` 可调）
- 同时服务于**链构象分析**与**结晶行为分析**（设计大纲第 16 章）

### 4.2 界面相容性分析

#### 密度分布

- 沿模拟盒第 `axis` 个**盒矢量方向**（0=a, 1=b, 2=c）统计各组分的质量密度（g/cm³）或数密度
- 用**分数坐标**做直方图，再按时间窗口内的**平均盒尺寸**归一化 → 对正交盒与三斜盒（如 GROMACS 截角八面体）都成立，且不受 NPT 盒子漂移影响
- 输出：Density–Position 曲线 + 归一化曲线 ρ/ρ_bulk、体相密度、平均密度
- **口径写进结果本身**（1.0.1）：新增 `密度口径` 与 `密度单位`，明确本次是
  **质量密度 (g/cm³)** 还是**数密度 (1/Å³)**。两者数值差一个摩尔质量量级
  （水的体相：0.997 g/cm³ vs 0.0334 个/Å³），导出成表后只看"体相密度 0.168"
  无法分辨是哪个口径，因此不能只藏在纵轴标签与 metadata 里。
  实测一致性：同一水分布，质量密度 0.9821 g/cm³ ↔ 数密度 0.1314 1/Å³
  （按每原子平均质量 4.504 u 换算，相对偏差 0.07%）。
- 法向（`axis`）始终使用**用户选择的方向**，工具不会用"自动建议方向"覆盖它

#### RDF — 径向分布函数

$$g(r)=\frac{n(r)}{N_a N_b \cdot \frac{4}{3}\pi\left(r_{i+1}^3-r_i^3\right)/V_{box}}$$

- 支持 A-A / B-B / A-B 任意组合，一次算出全部配对
- 输出：g(r) 曲线、第一峰位置、第一峰高度、第一极小位置、**第一壳层配位数**
  配位数按 $n=\rho_B\int_0^{r_{min}}4\pi r^2g(r)\,dr$ 计算（含数密度，不是裸积分）
- `compare_halves=True` 时额外给出"模拟前半段 vs 后半段"的 RDF，用于观察结构有序化趋势（设计大纲第 15.2 章）
- `exclude_bonded=True` 可剔除成键（1-2）原子对
- 当 `rmax` 超过最小盒高度的一半时会给出提示

#### 接触分析

定义 $r<r_{cutoff}$ 为发生接触。输出：

- 接触对数随时间变化、参与接触的 A 组原子数随时间变化
- 最小原子间距随时间变化
- 平均接触对数、最大接触对数
- **每个 A 组原子的「平均接触数」**（该原子每帧接触到几个 B 原子，对帧取平均）
- **接触对占据率**（某一对 (i∈A, j∈B) 处于接触的帧数 / 总帧数）及其分布
- **配位数分布**（每个 A 原子**每帧**的瞬时接触数直方图；给出均值 ± 标准差与众数）：
  比平均值多出「分布宽度」这一维——实测水在分子内模式下是**恰好在 3 的 δ 分布**
  （平均 3.000、标准差 0.00），而分子间模式为 65.0 ± 8.3，两种配位环境一眼可分
- 单个 A 组原子的接触概率分布

> ⚠️ 关于"接触概率"：`接触概率（存在接触的帧比例）` 定义为
> `mean(每帧接触对数 > 0)`，即**只要有任意一对原子接触就算"有接触"**。
> 稠密体系里几万个原子对中永远至少有一对落在 cutoff 内，因此该值**恒为 1**
> （实测 AdK 蛋白×水、糖蛋白×糖、46 polymer×ion 全部为 1）——它不是算错了，
> 而是这个定义本身没有区分度，**不能用它比较不同体系**。结果里会显式给出
> `接触概率是否饱和` 的判定与说明。要看接触强度请用「平均接触数」，要看
> "黏得牢不牢"请用「接触对占据率」（它才是有区分度的概率：区分"始终黏在一起"
> 与"偶发碰到"）。
>
> 代价：占据率需要逐帧合并接触对 key，实测在 AdK 蛋白×水（6.5 万对/帧）上约
> +0.14 s/帧；帧数超过 `occupancy_max_frames`（默认 300）时自动跳过并说明。

最小间距采用"从 cutoff 出发逐步放大截断距离"的搜索策略，兼顾速度与正确性。

#### 界面宽度分析

1. 两个组分各沿指定方向求密度分布，用体相值归一化得 $f_A(x)$、$f_B(x)$；
2. **界面位置**取 $f_A$ 与 $f_B$ 的交点（两组分各占一半的位置）；
3. **界面宽度**取该界面处 $f$ 从 0.9 变到 0.1 的距离（10–90 判据）；
4. 同时给出**误差函数拟合**结果：拟合 $f(x)=\frac12\left[1\pm\operatorname{erf}\left(\frac{x-x_0}{\sqrt2\sigma}\right)\right]$，
   报告 $\sigma$ 与 $2.5631\sigma$，便于与文献对比。拟合会被质量校验（R²>0.9 且 σ 合理）后才采纳。

##### 板层体系的两个界面（重要）

板层（slab）体系在**周期性边界下必然出现两个界面**（例如水层上下各一个油相界面）。
本工具不武断地只报一个：

- **所有交点都按 z 顺序列出**，各自给出位置与宽度（`界面位置` / `界面2 界面位置` …）；
- **每个界面的宽度都在局部测量**：只取该界面两侧、同一过渡区内的 0.9 / 0.1 穿越点，
  并要求这一对穿越点分处界面两侧、且都落在界面附近的搜索窗口内。
  这样板层的两个界面不会互相串扰。

> **为什么必须局部测量**：早期版本对整条曲线全局找 0.9 与 0.1 穿越点，在双界面体系里
> 会把**一个界面的 0.9** 与**另一个界面的 0.1** 配对，报出 89 Å 这种荒谬宽度
> （真实值约 10 Å）。现在每个界面独立测量，实测两侧界面为 9.02 Å 与 8.45 Å。

- **跨越周期边界的界面**也能测量：轮廓会按盒长做周期延拓后再找穿越点
  （否则落在盒边缘的那个界面会因为"过渡还没走完"而无法测量）；
- **erf 拟合的台阶取向由数据自身判定**（先看界面左右哪侧密度高，再选上升或下降的 erf），
  否则同一条曲线上的两个界面只有一个能拟合上；
- 两个界面都通过拟合时，`界面判据可靠性` 会明确标注为板层体系；
  两个界面都无法拟合时，会说明这些交点只是**密度涨落**，"界面宽度"不能按界面宽度解读
  （蛋白水溶液这类均匀体系就是这种情况）。

> **1.0.1：未分层就拒绝给数。** 1.0.0 虽然会提示"不能按界面宽度解读"，但**仍然把
> 数值输出**在 `界面宽度 10-90 (Å)` 里——实测 AdK 均匀溶液（根本没有界面）
> 被判成「高（板层体系，检测到 2 个界面，erf 拟合通过）」并给出 **36.6 Å** 的
> "界面宽度"（盒长才 80 Å）。现在新增两道判据：
> ① **是否真的分层**：ρ_A/ρ_bulk 必须同时接近 1（A 相内）与接近 0（B 相内），
> 否则说明两组分只是密度涨落互相穿越；② **过渡尺度是否远小于盒长**
> （必须 < 盒长的 1/4）。任一条不满足即：
> `1D 台阶模型是否适用 = 否`、`界面宽度是否可用 = 否`、`界面位置是否可用 = 否`，
> **宽度与位置键整体移除**，只留一个如实标注的 `密度涨落特征尺度 (Å)（不是界面宽度）`。
> 真实板层体系（Abeta 水/DCE）不受影响：仍给出 9.02 / 8.45 Å 与「高」的可靠性。

### 4.3 结晶行为分析

#### 链段取向

- **链段定义（1.0.1 起默认 `repeat`）**：
  - `repeat`（**默认**）：**化学重复单元**——残基内连接相邻残基的那两个原子的连线
    （蛋白的 N→C、糖的 O4→C1、合成高分子的单体轴）。识别不出时回退几何法，
    并在 metadata 标 `segment_source=geometric segment orientation`、
    `segment_fallback=True`；
  - `backbone`：几何法（键连接图最长路径上相距 `stride` 个键的原子对）。
    它只是"几何上连成一串的原子"，**不保证**等于化学重复单元；
  - `bonds`（所有重原子键）、`custom`（用户给定原子对）。
- **多分子集合平均（1.0.1 起）**：取向是有序度的集成量，分析对象是**整个组分**
  （该组分的全部分子），而不是"最大的一条链"。结果里会写明链段来自多少个分子。
  实测 46 体系 polymer：432 个化学重复单元来自 **253 个分子**（旧版只算最大的一条链）。
- **取向参数 S** 由二阶取向张量 $\mathbf Q=\left\langle\frac{3\mathbf u\mathbf u^T-\mathbf I}{2}\right\rangle$ 的最大本征值给出：
  S=0 完全无序，S=1 完全取向。**不需要外部参考方向**，可用于无外场的本体体系
- **链段数不足则拒绝给数**：S 的统计不确定度约 $\sqrt{2/5N}$，链段数少于 10 时
  误差与 S 同量级（且链段数 = 1 时 S 恒等于 1），结果里只说明原因、不输出 S；
  链段数 ≥ 2 时同时给出 `S 估计标准误 (≈√(2/5N))`
- 同时给出相对给定参考轴的二阶序参数 $P_2=\left\langle\frac{3\cos^2\theta-1}{2}\right\rangle$
- 输出：S–Time、P₂–Time、取向角分布、取向矢 (director) 随时间变化

#### 结构有序度

三个定义明确的分量，统一到 **0 = 完全无序、1 = 完全有序**：

| 分量 | 定义 | 是否需要外部参考 |
|---|---|---|
| 取向有序度 $S$ | 取向张量最大本征值 | 否 |
| 二面角有序度 | $-\langle\cos 3\varphi\rangle$（负值截断为 0） | 否 |
| 局部结构有序度 | $(g_{peak}-1)/(g_{ref}-1)$，截断到 [0,1] | **需要** |

**多分量有序度指数** = 各参与分量按权重的加权平均。

> **1.0.1 改名**：原「综合（结构）有序度指数」已更名为**「多分量有序度指数」**，
> 因为它的本质是"若干分量按**自定义权重**加权"，不是结晶度，也不该被当成
> 单一物理量。结果里新增 `指数名称`、`指数包含的分量`、`指数是否可定义`
> 与权重理由；某分量不可用（该组分没有链段/没有二面角）时其权重**强制置 0**
> 并写明，而不是让它悄悄按 0 参与平均。
>
> **分量不可用时不给出指数值**：若三个分量都不可用（例如把水或离子当分析对象：
> 既无取向链段、又无二面角、也未给 `g_ref`），指数返回 **nan** 并标记
> `指数是否可定义 = 否`——0 会被误读成"完全无序"，nan 才是正确表达。

> ⚠️ 关于 `g_ref`（重要）：
> RDF 的堆积峰高度**依赖体系的数密度**——同一个致密相放在大盒子里 $g_{peak}$ 就大、
> 放在小盒子里就小，所以它的绝对值不能跨体系比较，也不能直接当作有序度。
> 因此默认 `g_ref=None`：**局部结构分量不参与综合指数**，只作为参考量输出
> （结果里会给出「RDF 堆积峰高度」的数值）。等使用者在自己的体系里确定了
> "完全有序态"对应的峰高后，再通过 `g_ref=`（CLI 用 `--g-ref`）传入，
> 该分量才会计入综合指数。
>
> 按设计大纲第 18、19 章的要求，这是一个**可配置的一般性结构有序性指标**，
> 用于比较同体系不同时间 / 不同体系的**相对**有序程度，
> **不等同于绝对结晶度**。若要定量结晶度，请按具体研究体系确定判据后调整权重与参考值。

以 AdK 水溶液为例（各向同性、无序体系）：

| 配置 | 综合有序度指数 | 说明 |
|---|---|---|
| `g_ref=None`（默认） | **0.012** | 只有取向 + 二面角分量 → 正确反映"无序" |
| `g_ref=30`（人为给参考值） | 0.156 | 三分量；其中 RDF 堆积峰 = 13.8 |

默认配置把这个各向同性体系判为 0.012（接近 0），符合物理预期。

### 4.4 辅助分析：MSD

$$\mathrm{MSD}(t)=\left\langle|\mathbf r(t)-\mathbf r(0)|^2\right\rangle$$

- 跨周期性边界通过**最小镜像位移累加**追踪粒子（比 `NoJump` 更可控），
  并报告"最小镜像失效比例"作为可靠性诊断
- 输出：MSD–τ 双对数曲线、线性区拟合、$D$（Å²/ps 与 m²/s）、$\mathrm{MSD}\propto t^\alpha$ 的 α、R²
- **D 带标准误**（1.0.1）：优先用**分块平均**（把轨迹切成若干时间块、各自独立拟合，
  取各块 D 的散布）；块数不足 3 块时退回拟合协方差 × **实测**残差 AR(1) 修正。
  误差来源会写进结果与说明里。实测（合成布朗运动，真值 2.0e-10 m²/s）：
  报出 **2.195e-10 ± 9.6e-12 m²/s（偏差 2.04σ）**；而只算 OLS 协方差会给出
  5.3e-13，**低估 18.2 倍**——这就是必须做相关修正的理由。
- 扩散系数由 $\mathrm{MSD}=2\cdot dim\cdot D\cdot t$（三维即 6Dt）的线性区斜率给出

> **可靠性判定同时看「最小镜像失效比例」，而不只看 R² 与 α。**
> 失效来自"帧间隔内的位移超过最小盒高度的一半"；这种误差是**随机**的，
> 它会让 MSD 曲线依然平滑、线性（R² 甚至接近 1），但绝对数值已被污染。
> 因此失效比例 > 5% 时会在 `拟合可靠性` 里明确降级，> 20% 时直接标注
> 「**不建议引用**」并建议缩小帧间隔。实测例子：某数据集帧间隔 2 ns，
> 水的失效比例 68%，其 D 与 DCE 的 D 几乎相同（3.56 vs 3.56 ×10⁻¹⁰ m²/s）
> ——这正是被同一份回绕噪声主导的典型征兆。

## 5. 关键设计说明

### 5.1 周期性边界条件

分子内几何量（Rg、端到端距离、二面角）在**按分子连通性展开（unwrap）后**的坐标上计算。
这一条非常关键：在测试轨迹 `adk_oplsaa` 中，蛋白被盒边界切断——

| 量 | 裸坐标（未处理） | 展开后（本工具） |
|---|---|---|
| Rg (Å) | 24.38 | **19.65** |
| 最大原子间距 (Å) | 89.2 | 62.1 |

19.65 Å 与 AdK（214 残基）的文献值（约 19–20 Å）吻合，24.38 Å 是 PBC 假象。
本工具在展开失败时（例如含零质量虚拟位点的碎片）会自动逐级退让
（`reference='com'` → `'cog'` → `None` → 按残基 → 最小镜像），不会直接报错。

空间分布量（密度、RDF、接触）按**最小镜像**处理，与 `gmx rdf` / `gmx density` 的物理含义一致。

### 5.2 单位约定

工具内部统一使用 GROMACS / MDAnalysis 原生单位，只在绘图和导出时做可读性转换：

| 量 | 单位 |
|---|---|
| 长度 | Å |
| 时间 | ps（绘图时若总时长 ≥ 1000 ps 自动改用 ns） |
| 质量 | amu |
| 电荷 | e |
| 密度 | g/cm³（= amu/Å³ × 1.66054） |
| 扩散系数 | Å²/ps 与 m²/s（×1e-8） |

### 5.3 选择器

`mdta.selection.select()` 支持按原子名、原子类型、residue 名、residue 编号、原子编号、
段名、自动识别的组分类型，以及 `within/around ... of ...` 空间选择，
也可以直接写 MDAnalysis 选择语句。

组分自动识别把 residue 归类为 `protein` / `nucleic` / `polymer` / `water` / `ion` / `other`，
`polymer` 即"未被识别为蛋白/核酸/水/离子的中大分子残基"——高分子体系会自动落入这一类。

"链"按键连接图的连通分量切分（有键信息时），并按 `（segid, resname）` 归类汇总，
因此上万个水分子只占一行，而高分子链会逐条列出。

### 5.4 帧选择

`select_frames()` 的语义：

- `start_ps` / `stop_ps`：参与分析的时间区间（含端点）
- `equil_ps`：等价于 `start_ps = max(start_ps, equil_ps)`，用于排除未平衡的初期数据
- `interval_ps`：抽帧间隔，取距目标时间最近的帧
- `max_frames`：等间隔抽样上限，用于控制计算量

端点判定使用**相对容差**（`1e-6 × 时间量级`），因为 XTC 的时间戳以 float32 存储，
`900.000061` 这样的值不应该被 `stop_ps=900` 漏掉。

## 9. 已知限制与后续扩展

### 限制

1. **界面宽度判据**对**分层/界面体系**才有物理意义。对均匀混合体系（如本测试的蛋白水溶液），
   该指标只反映密度涨落，不能解释为真实界面宽度——工具会在结果说明里明确提示
   （`界面判据可靠性 = 低`，并说明交点只是密度涨落）。
   > 建议：用合成体系验证过算法正确性（见自检中的界面项），实际研究时请确认体系确实是分层的。
2. **绝对结晶度**未实现。设计大纲第 19 章已说明具体算法需要按研究体系确定，
   本工具给出的是可配置的相对有序度指标。
3. **最小镜像近似**要求距离小于最小盒高度的一半。
   - RDF 的 `rmax` 过大会给出提示；配位数用**原始**原子数的数密度计算，
     与 RDF 是否抽稀无关。
   - MSD 报告"最小镜像失效比例"，并**以此降级可靠性判定**：失效比例 > 5% 时提示
     D 可能偏离真值，> 20% 时标注「不建议引用」。
     实测：AdK 体系为 1.0%（D = 3.5×10⁻⁹ m²/s，α≈1.07，可信）；
     某帧间隔 2 ns 的数据集为 57–68%（此时连 α 都不可信，水与 DCE 的 D 几乎相同）。
   - **帧间隔的选法**：需保证"帧间隔内典型位移 < 最小盒高度的一半"。
     水在 300 K 下 D≈2.5×10⁻⁹ m²/s，帧间隔 100 ps 时位移约 9 Å；
     2 ns 时约 40 Å——若盒高只有 60 Å，就已经失效了。
4. RDF 对大体系（上万原子）自配对较慢。流水线会自动把水组分降为氧原子；
   其余组分若过大，会自动等间隔抽稀到 6000 个代表原子（g(r) 与配位数都不受影响，
   见自检项），也可以用 `--primary`/选择语句抽取代表性子集。
5. 格式支持范围见第 1 节表格。`.tpr` 与 `.gro` 已在真实体系上充分实测
   （两者键表完全一致）；`.pdb` / `.psf` / `.prmtop` 走 MDAnalysis 原生读取路径，
   已做接口适配但未逐一实测；`.top` 被**明确拒绝**并给出可操作提示。

### 可扩展方向

- 结构因子 S(q)（设计大纲第 18 章列为"可能包括"）
- `plotly` 交互式图形
- PDB/GRO 单帧结构查看器
- 密度分布的二维投影（DensityAnalysis 的 2D 模式）
- 多体系结果自动对比图（批量分析已产出 `batch_summary.xlsx`，可再加对比图）

## 附：常见问题

**Q：`--interval` 设多大合适？**
按分析类型：Rg / 端到端距离 / 密度 / RDF 对时间相关性不敏感，可取大一点（100–500 ps）；
MSD 需要较密的帧才能分辨短时间行为；二面角分布建议帧数 ≥ 50 才有统计意义。

**Q：报错"原子数不匹配：拓扑 X vs 轨迹 Y"？**
`.tpr` 与 `.xtc` 不是同一次模拟。请确认两个文件配套。

**Q：报错"rmax 超过最小盒高度的一半"？**
把 `--rmax` 减小到最小盒高度的一半以下（工具会在 note 里给出具体阈值）。

**Q：想分析多条高分子链？**
先用 `python mdta_cli.py chains -t sys.tpr` 看链清单，再用
`--primary "segid seg_0_PE"` 选中某一段的全部链，或在 Python 里用
`mdta.selection.chains()` 逐条取，循环调用 `analyze_rg`。

**Q：结果图里的中文变成方框？**
`mdta/plotting.py` 会自动搜索 Microsoft YaHei / SimHei / Noto Sans CJK 等字体。
若都找不到，图会正常生成但中文缺失；可把系统字体名加进 `_FONT_CANDIDATES` 列表。

**Q：界面文字发虚 / 模糊？**
工具启动时会自动开启高 DPI 感知并按显示缩放调整，正常情况下不会模糊。
若仍然模糊，通常是系统 DPI 探测异常，用 `$env:MDTA_GUI_SCALE="1.5"` 手动指定
（值 = 系统缩放百分比 ÷ 100）即可。
